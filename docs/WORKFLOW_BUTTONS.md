# Кнопка запуска бизнес-процесса в карточке сделки

Модуль добавляет собственный тип поля `sinedis_bp_button`. Каждое поле этого типа
отображает одну настраиваемую кнопку; для нескольких действий создайте несколько полей.
Существующие роботы продолжают работать. Новая функция по умолчанию выключена.

## Включение

1. Обновите приложение и примените миграции: `uv run alembic upgrade head`.
2. В локальном приложении Битрикс24 добавьте разрешение **Встраивание приложений (`placement`)**.
   Сохраните `crm` и `bizproc`. Методы `profile`, `user.admin`, `app.info` используются
   для проверки контекста и полномочий. Установка должна выполняться администратором:
   серверный запуск `bizproc.workflow.start` использует сохранённые полномочия установки.
3. Установите в `.env` `WORKFLOW_BUTTONS_ENABLED=true` и перезапустите API.
4. Переустановите приложение или выполните `uv run python -m app.bitrix.register_extensions`.
   Это добавляет/обновляет тип поля без удаления роботов или существующих полей.
5. В карточке сделки создайте пользовательское поле типа
   **«Запуск бизнес-процесса SINEDIS»**. Поле должно быть одиночным и необязательным.
   Если редактор вашего портала не предлагает тип, администратор может создать поле через REST:

   ```javascript
   BX24.callMethod('app.info', {}, function (result) {
     if (result.error()) return;
     BX24.callMethod('crm.deal.userfield.add', {fields: {
       FIELD_NAME: 'SINEDIS_BUTTON',
       USER_TYPE_ID: 'rest_' + result.data().ID + '_sinedis_bp_button',
       XML_ID: 'SINEDIS_BUTTON', MULTIPLE: 'N', MANDATORY: 'N',
       EDIT_FORM_LABEL: {ru: 'Действие со сделкой'},
       LIST_COLUMN_LABEL: {ru: 'Действие со сделкой'}
     }}, function (created) { console.log(created.error() || created.data()); });
   });
   ```

   Код созданного поля получите через `crm.deal.userfield.list` (обычно
   `UF_CRM_SINEDIS_BUTTON`). Не используйте код типа в качестве кода поля.
6. Откройте сохранённую сделку в режиме просмотра. В поле нажмите **«Настроить кнопку»**.
   Администратор задаёт подпись, номер шаблона, параметры, цвет, размеры и номера сотрудников.
   Настройки относятся к полю на конкретном портале и действуют во всех его сделках.
7. Включите кнопку и сохраните настройки. Вернитесь к кнопке или откройте карточку заново.

Страница настроек открывается в том же встроенном окне поля. Отдельное приложение
для каждого процесса, изменение исходного кода Битрикс24 или переключение существующей
API-установки на иной обработчик не требуются. Не открывайте страницы приложения вне
Битрикс24: библиотеке нужен контекст встроенного окна.

## Права и запуск

- Сохранение настроек, просмотр журнала и разблокировка доступны только администраторам.
- Пустой список сотрудников разрешает запуск только администраторам.
- Для обычного сотрудника нужны включённая кнопка, его номер в списке и доступ
  к сделке. Доступ к сделке проверяется запросом с ключом сотрудника.
- Разрешение на кнопку означает право инициировать конкретный процесс через сервер
  с административными полномочиями приложения. Это отдельное разрешение приложения,
  а не воспроизведение штатных прав ручного запуска Битрикс24.
- Браузер не выбирает шаблон или параметры запуска: сервер берёт их из настроек поля.
- Проверяются идентификатор приложения и активная установка портала; адрес REST
  берётся только из сохранённых сведений портала. Административные ключи не передаются браузеру.
- В режиме редактирования и до сохранения сделки запуск недоступен.

REST-запуск требует лицензии Битрикс24, поддерживающей бизнес-процессы.
Перед использованием проверьте шаблон и его параметры на тестовой сделке.

## Защита от повторных запусков

Запрос получает случайный идентификатор. Повтор с тем же идентификатором возвращает
сохранённый результат. Транзакционная блокировка портала сериализует резервирование;
повторное нажатие с другим идентификатором в пределах паузы также отклоняется.
Запись `starting` сохраняется **до** обращения к Битрикс24.

- `started`: Битрикс24 вернул идентификатор процесса. Это подтверждение запуска,
  а не успешного выполнения всего процесса.
- `blocked`: процесс запущен, включена ручная блокировка следующих запусков.
- `unknown`: результат запроса неопределён; автоматический повтор запрещён.
- `starting`: запрос ещё выполняется либо сервер прервался после резервирования.

Пауза между запусками не определяет, завершился ли предыдущий процесс. Для важных
действий включите **«Блокировать следующие запуски до ручной разблокировки»**.
Автоматический контроль завершения длительного процесса в этой версии отсутствует.

В журнале показаны последние 50 записей: время, сделка, сотрудник, шаблон,
идентификаторы запуска и процесса, состояние, сотрудник, снявший блокировку.
При `unknown`/`starting` сначала проверьте процессы сделки в Битрикс24. Только после
проверки нажмите **«Разблокировать»**. Разблокировка доступна не раньше чем через
пять минут после запроса и сама не останавливает процесс в Битрикс24.
Неопределённые запросы не передаются в очередь роботов, которая имеет другой порядок повторов.

## Проверки перед использованием

1. Запуск администратором и сотрудником из списка создаёт один процесс нужного шаблона
   именно в открытой сделке.
2. Сотрудник вне списка и сотрудник без доступа к сделке не могут запустить процесс.
3. Двойное нажатие создаёт один процесс; повтор в пределах паузы отклоняется.
4. После включения ручной блокировки следующий запуск разрешается только после проверки
   результата и снятия блокировки администратором.
5. Стандартное поле или поле другого приложения не принимается в настройках.
6. Существующие роботы успешно регистрируются и выполняются после обновления.

Автоматические проверки: `make format-check`, `make lint`, `make test`.
Для проверок конкурирующих запросов используйте отдельную PostgreSQL-базу,
примените к ней миграции и задайте `TEST_DATABASE_URL`. Не используйте рабочую базу.
